# 端到端验证与人工检查

## Docker Playwright 场景

运行命令：

```powershell
docker compose -f docker-compose.yml -f docker-compose.e2e.yml up -d --force-recreate api worker frontend
docker compose -f docker-compose.yml -f docker-compose.e2e.yml --profile test run --rm e2e pnpm test
```

全部场景使用容器内 Chromium 和 Fake provider；Playwright 不依赖宿主机 Node 或浏览器。

| # | 场景 | 测试文件 |
| --- | --- | --- |
| 1 | 任务中心加载并显示 API 就绪状态 | `e2e/tests/health.spec.ts` |
| 2 | 创建/编辑草稿、上传和移除资料、刷新后读取持久化数据 | `e2e/tests/task-draft.spec.ts` |
| 3 | 任务名称搜索；375、768、1440 像素视口无页面级横向溢出 | `e2e/tests/task-hardening.spec.ts` |
| 4 | 新建任务拒绝不在 3–50 页范围内的页数 | `e2e/tests/task-hardening.spec.ts` |
| 5 | 不支持的参考文件得到可理解的格式错误 | `e2e/tests/task-hardening.spec.ts` |
| 6 | CORS 精确允许本地前端来源并拒绝其他来源 | `e2e/tests/task-hardening.spec.ts` |
| 7 | 任务草稿过期版本写入返回稳定 `VERSION_CONFLICT` | `e2e/tests/task-hardening.spec.ts` |

## 发布前人工检查清单

- [ ] 使用键盘从任务中心开始完成创建、上传、需求确认、大纲编辑、评估操作和结果导出；焦点顺序清晰，焦点状态可见，弹窗/抽屉关闭后焦点返回触发控件。
- [ ] 用屏幕阅读器检查页面标题层级、表格标题、状态变化、上传错误、评估问题列表、聊天发送状态和下载控件名称。
- [ ] 在 320/375 像素手机、768 像素平板和桌面宽度逐页查看六个页面；任务表格局部横向滚动，主体页面无横向溢出，固定/粘性元素不遮挡内容。
- [ ] 检查空任务、上传中/失败、需求澄清、大纲审核、生成中、取消、评估未通过、自动修订上限和最终结果状态。
- [ ] 下载中文 Markdown 并使用 UTF-8 编辑器打开；核对页码、标题、要点和引用来源。
- [ ] 配置隔离的 OpenAI-compatible 测试账号，分别验证首选模型成功、暂时故障触发备用模型、全部模型暂时失败后任务可恢复；确认实际模型和切换记录对用户可见。

屏幕阅读器、真实供应商端点和公网部署安全不由 Fake provider 的自动化结果代替。执行人应记录浏览器/屏幕阅读器版本、日期和发现的问题，再确认发布。
