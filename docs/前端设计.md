> 文档版本：1.0  
> 编写日期：2026-09-28  
> 依据文档：[需求分析.md](./需求分析.md)、[开发指导.md](./开发指导.md)

> 适用范围：SlideAI 首期 Web 前端  
> 主要读者：前端实现模型、前端开发者、测试人员、设计验收人员

## 1. 文档目标

本文把产品需求、技术设计和效果图整理为可直接实现的前端规范，重点解决以下问题：

- 明确真正需要实现的页面、路由和页面间跳转；
- 固化颜色、字号、间距、布局和响应式规则；
- 固化流程条、顶部导航、任务头、上一步按钮、底部操作栏、聊天抽屉等通用组件；
- 明确不同任务状态在前端的呈现与允许操作；
- 明确哪些效果图内容只用于表达设计意图，不能机械照搬；
- 保证系统始终呈现“结构化演示文稿文字内容”，不误做成 PPT 视觉编辑器。

本文是前端实现的直接依据。低级模型不得依据单张效果图自行发明页面、改变通用组件、修改固定文案或加入首期范围之外的视觉功能。

## 2. 依据优先级与解释原则

不同资料出现差异时，按以下顺序处理：

1. `需求分析.md`：决定产品范围、功能和验收标准；
2. `开发指导.md`：决定前后端边界、接口、状态和工程约束；
3. `前端设计.md`：决定前端信息架构、布局、交互和通用组件；
4. `ui-mockups-final/*.png`：只作为配色、密度和大致布局参考。

效果图不是像素级实现合同。效果图出现下列情况时，以本文为准：

- 导航名称、按钮名称或状态文案不一致；
- 同一组件在不同效果图中的颜色或尺寸不一致；
- 示例日期、任务名称、模型名称或文件名称与实际数据不同；
- 为展示多个能力而把不会同时出现的状态放在同一画面；
- 效果图遗漏了 loading、empty、disabled、error 或窄屏状态；
- 视觉内容与实际产品范围冲突。

## 3. 产品形态与设计边界

### 3.1 产品形态

SlideAI 是演示文稿文字内容生成与优化工具。用户在前端完成需求填写、资料上传、大纲确认、过程查看、质量检查、聊天修改和 Markdown 导出。

前端应被理解为“文档生成工作台”，不是 PPT 设计软件。

### 3.2 禁止出现的设计

首期页面中禁止出现：

- 16:9 幻灯片画布；
- PPT 页面缩略图；
- 模板、主题、母版、字体搭配或配色方案选择；
- 图片布局、图表布局、动画和转场；
- 拖拽摆放文字框、图片框或形状；
- “所见即所得”的 PPT 视觉排版工具栏；
- 暗示系统已经生成视觉成品的预览图。

“第 8 页”“15 页内容”等表达只代表结构化文稿的逻辑页面。结果页必须以连续文字、标题、要点、备注、引用和 Markdown 源码呈现。

### 3.3 页面与状态的区别

首期只有 6 个核心页面。聊天助手、模型调用记录、确认提示、文件错误和自动修订上限都是页面内部状态、抽屉或对话框，不单独创建顶级页面。

## 4. 页面信息架构

### 4.1 核心页面与路由

| 编号 | 页面 | 路由 | 主要职责 | 效果图参考 |
| --- | --- | --- | --- | --- |
| P01 | 任务中心 | `/tasks` | 查看、筛选、恢复和管理任务 | `01-task-center.png` |
| P02 | 新建/编辑任务 | `/tasks/new`、`/tasks/:taskId/edit` | 填写需求、选择模型、上传资料 | `02-create-task.png` |
| P03 | 结构化需求确认 | `/tasks/:taskId/requirement` | 检查解析结果、处理缺失和冲突 | `03-requirement-review.png` |
| P04 | 大纲编辑 | `/tasks/:taskId/outline` | 编辑大纲、分配页数、使用大纲助手 | `04-outline-editor.png` |
| P05 | 生成进度 | `/tasks/:taskId/progress` | 查看节点进度、错误、模型降级和人工处理 | `05-generation-progress.png` |
| P06 | 文字结果 | `/tasks/:taskId/result` | 查看文字内容、评估、聊天修改和 Markdown 导出 | `06-text-result.png` |

根路由 `/` 重定向到 `/tasks`。不得再创建“资料检索页”“模型调用页”“质量评估页”“Markdown 下载页”等独立顶级页面。

### 4.2 页面跳转主流程

```text
任务中心
  -> 新建/编辑任务
  -> 结构化需求确认
  -> 大纲编辑
  -> 生成进度
  -> 文字结果
```

这只是正常路径。实际路由必须由任务状态决定，不能假设用户总是从上一步连续进入。

### 4.3 按任务状态恢复路由

| 任务状态 | 默认进入页面 | 说明 |
| --- | --- | --- |
| `DRAFT` | 新建/编辑任务 | 恢复未提交的表单和文件 |
| `FILES_PROCESSING` | 新建/编辑任务 | 文件区持续显示解析状态 |
| `READY` | 新建/编辑任务 | 用户可以开始需求解析 |
| `WAITING_REQUIREMENT_INPUT` | 结构化需求确认 | 展示缺失或冲突字段 |
| `WAITING_OUTLINE_CONFIRMATION` | 大纲编辑 | 展示可编辑大纲 |
| `RUNNING` | 生成进度 | 按当前节点展示状态 |
| `WAITING_USER_FEEDBACK` | 生成进度 | 展示人工处理区域 |
| `FAILED_RETRYABLE` | 生成进度 | 展示失败节点和恢复操作 |
| `FAILED_FINAL` | 生成进度 | 只允许查看详情或返回任务中心 |
| `COMPLETED` | 文字结果 | 展示最新可用版本 |
| `CANCELLED` | 生成进度 | 只读展示取消前的现场 |

前端必须提供唯一的 `resolveTaskRoute(task)` 方法处理上述映射。任务中心、刷新恢复和通知跳转都调用该方法，禁止各页面自行写一套判断。

## 5. 全局视觉系统

### 5.1 视觉方向

整体使用浅天蓝和白色，风格清爽、专业、可信。界面需要有足够留白和明确层级，但不能为了“精致”加入无业务意义的渐变、玻璃效果、装饰图表或大面积插画。

### 5.2 颜色令牌

所有颜色必须通过 CSS 变量或 Element Plus 主题变量引用，禁止页面内直接散落十六进制颜色。

```css
:root {
  --color-primary-600: #168cf0;
  --color-primary-700: #0f78d4;
  --color-primary-800: #0b65b5;
  --color-primary-100: #dff2ff;
  --color-primary-050: #eef8ff;

  --color-page-bg: #f4faff;
  --color-header-bg: #ffffff;
  --color-surface: #ffffff;
  --color-surface-muted: #f8fbfe;

  --color-text-strong: #102a56;
  --color-text: #263f66;
  --color-text-muted: #6b82a0;
  --color-border: #d6e6f3;
  --color-border-strong: #bcd6ea;

  --color-success: #16a66a;
  --color-success-bg: #e8f8f1;
  --color-warning: #f5a623;
  --color-warning-bg: #fff6df;
  --color-danger: #e9485b;
  --color-danger-bg: #fff0f2;
  --color-info: #3aa5f4;
  --color-info-bg: #eaf6ff;

  --color-focus: #78bffc;
  --shadow-panel: 0 8px 24px rgba(31, 92, 140, 0.08);
}
```

使用规则：

- 主操作只使用 `primary`；同一区域最多一个实心主按钮；
- 成功只使用绿色，警告只使用橙色，失败只使用红色；
- 不用颜色作为唯一状态提示，必须同时有图标和文字；
- 页面背景用浅蓝，数据承载区域用白色；
- 禁止自行增加紫色、粉色或高饱和渐变作为主要视觉语言。

### 5.3 字体与字号

```css
font-family:
  Inter,
  "PingFang SC",
  "Microsoft YaHei",
  "Segoe UI",
  sans-serif;
```

| 类型 | 字号 | 字重 | 行高 | 用途 |
| --- | ---: | ---: | ---: | --- |
| 页面标题 | 30px | 700 | 42px | 页面主标题 |
| 任务标题 | 24px | 700 | 34px | 任务上下文标题 |
| 区域标题 | 20px | 600 | 28px | 主面板标题 |
| 小节标题 | 16px | 600 | 24px | 卡片、表格或正文小节 |
| 正文 | 14px | 400 | 22px | 表单说明、正文、消息 |
| 控件文字 | 14px | 500 | 20px | 按钮、输入框、标签页 |
| 辅助文字 | 12px | 400 | 18px | 时间、计数、提示 |

正文内容区域可使用 15px、24px 行高以提高长文本可读性。不得通过缩小字体来塞入更多内容；优先滚动、折叠或分页加载。

### 5.4 间距、圆角和阴影

- 间距基数：4px；常用值为 8、12、16、20、24、32、40；
- 页面左右留白：桌面 32px，窄桌面 24px；
- 面板间距：16px 或 20px；
- 输入框圆角：6px；
- 按钮圆角：6px；
- 普通卡片圆角：10px；
- 主面板圆角：12px；
- 大容器圆角不得超过 16px；
- 普通区域只使用 1px 边框，不同时使用重阴影；
- `--shadow-panel` 只用于浮层、聊天抽屉或需要与背景分离的主面板。

### 5.5 图标

统一使用 Element Plus Icons 或同一套线性图标，不混用不同风格。默认 18px、2px 左右视觉笔画；状态图标可以使用填充圆形容器。

禁止使用 emoji 代替正式图标。箭头、更多、折叠、上传、文件、复制、下载、编辑、刷新和状态图标必须来自统一图标库。

## 6. 全局布局

### 6.1 应用外壳

```text
AppShell
├─ AppHeader
└─ RouterView
   ├─ PageHeader / TaskContextHeader
   ├─ WorkflowStepper（按页面显示）
   ├─ MainContent
   └─ FlowActionBar（按页面显示）
```

桌面端内容宽度规则：

- 页面内容最大宽度 1600px；
- 小于最大宽度时占满可用宽度；
- 居中显示；
- 页面最小可用宽度按 1024px 设计；
- 不把整个应用固定为效果图的 16:9 比例。

### 6.2 顶部导航 `AppHeader`

固定规范：

- 高度：56px；
- 背景：白色；
- 底部：1px 浅色边框；
- 左侧：`SlideAI` 品牌文字；
- 一级导航固定为：`任务中心`、`新建任务`；
- 右侧固定为：`使用帮助`、用户头像/菜单；
- 当前导航使用蓝色文字和 2px 底部指示线；
- 顶部导航不显示流程阶段、任务状态或模型状态。

禁止在部分页面把 `任务中心` 改成 `任务记录`。效果图中的 `任务记录` 统一纠正为 `任务中心`。

### 6.3 普通页面头 `PageHeader`

任务中心和新建任务使用普通页面头：

- 页面标题居中或左对齐由页面类型决定，但同一页面不切换；
- 标题下可有一行简短说明；
- 右侧最多一个主操作；
- 说明文字不超过一行，窄屏可换行。

### 6.4 任务上下文头 `TaskContextHeader`

结构化需求确认、大纲编辑、生成进度和文字结果统一使用：

- 左侧：任务名称；
- 紧随其后：目标页数、任务状态和版本标签；
- 右侧：当前页面允许的全局操作；
- 高度和上下间距一致；
- 任务名称过长时单行省略，悬停显示完整内容；
- 状态和版本来自服务端，禁止写死。

## 7. 不可变通用组件

本节组件属于设计系统固定部分。低级模型只能传入数据和允许的 variant，不能在单个页面复制并修改其样式。

### 7.1 流程条 `WorkflowStepper`

固定阶段和固定顺序：

```ts
const WORKFLOW_STAGES = [
  "需求解析",
  "大纲规划",
  "资料检索",
  "内容生成",
  "质量评估",
  "完成",
] as const
```

展示页面：结构化需求确认、大纲编辑、生成进度、文字结果。任务中心和新建任务不展示。

固定外观：

- 高度 72px；
- 白色背景、12px 圆角、1px 边框；
- 横向均匀分布；
- 节点之间使用 2px 连线；
- 不支持页面单独设置紧凑版、竖版或不同配色；
- 阶段名称不得缩写、改名或增删；
- 流程条默认不可点击，避免用户通过点击进入不允许的状态。

固定状态：

| 状态 | 图标与颜色 | 文字 |
| --- | --- | --- |
| `completed` | 绿色实心圆 + 对勾 | 深色 |
| `active` | 蓝色实心圆 + 序号或加载图标 | 蓝色加粗 |
| `warning` | 橙色实心圆 + 感叹号 | 橙色加粗 |
| `failed` | 红色实心圆 + 感叹号 | 红色加粗 |
| `pending` | 灰蓝描边圆 + 序号 | 灰色 |

页面只传入 `currentStage` 和 `stageStates`。不得在结果页隐藏流程条，也不得把完成态在某页画成蓝色、另一页画成绿色。

### 7.2 流程底部操作栏 `FlowActionBar`

用于新建任务、结构化需求确认和大纲编辑。固定在内容区域底部；内容不足一屏时贴近视口底部，内容较长时随页面滚动后保持 sticky。

结构固定：

```text
[上一步/空位]        [保存状态或辅助说明]        [次操作] [主操作]
```

#### `上一步` 按钮

- 固定文案：`上一步`；
- 固定左箭头图标；
- 固定为普通描边按钮；
- 位于操作栏最左侧；
- 不得改成“返回修改需求”“返回编辑原始需求”“返回上一页”等其他文案；
- 新建任务没有上一步时隐藏并保留布局空位，不显示 disabled 按钮；
- 结构化需求确认的上一步进入任务编辑页；
- 大纲编辑的上一步进入结构化需求确认页；
- 有未保存修改时，先显示统一离开确认对话框。

#### 主操作按钮

主操作在最右侧，使用蓝色实心样式。文案根据业务动作确定：

- 新建/编辑任务：`解析需求`；
- 结构化需求确认：`确认需求并生成大纲`；
- 大纲编辑：`确认大纲并开始生成`。

主操作按钮宽度可以按文案自适应，但高度、字号、圆角、loading 和 disabled 样式必须一致。

### 7.3 按钮 `AppButton`

固定 variant：

| Variant | 用途 |
| --- | --- |
| `primary` | 当前区域唯一主操作 |
| `secondary` | 次要但常用操作 |
| `outline` | 返回、取消、非破坏性选择 |
| `text` | 表格行操作、展开详情 |
| `danger` | 删除、取消任务等破坏性操作 |

规则：

- 高度默认 40px，紧凑表格按钮可用 32px；
- loading 时保留原宽度；
- disabled 不响应点击、不显示 hover；
- 破坏性操作不能使用蓝色主按钮；
- 同一行不出现两个视觉权重相同的主按钮；
- 图标始终位于文案左侧，只有明确的“继续”动作可在右侧使用箭头。

### 7.4 状态标签 `TaskStatusTag`

所有页面使用同一映射，不允许页面自行选择颜色：

| 业务状态 | 用户文案 | 颜色 |
| --- | --- | --- |
| `DRAFT` | 草稿 | 灰蓝 |
| `FILES_PROCESSING` | 资料处理中 | 蓝色 |
| `READY` | 待开始 | 灰蓝 |
| `RUNNING` | 生成中 | 蓝色 |
| `WAITING_REQUIREMENT_INPUT` | 等待需求确认 | 橙色 |
| `WAITING_OUTLINE_CONFIRMATION` | 等待大纲确认 | 橙色 |
| `WAITING_USER_FEEDBACK` | 等待用户处理 | 橙色 |
| `COMPLETED` | 已完成 | 绿色 |
| `FAILED_RETRYABLE` | 失败可重试 | 红色 |
| `FAILED_FINAL` | 失败 | 红色 |
| `CANCELLED` | 已取消 | 灰色 |

### 7.5 面板 `AppPanel`

固定结构：`header + optional actions + body + optional footer`。页面不得手写另一套标题行、圆角和边框。

- 白色背景；
- 12px 圆角；
- 1px 边框；
- 默认 24px 内边距；
- header 与 body 间距 16px；
- 只有警告和失败面板可以使用浅色语义背景；
- 避免面板内继续嵌套多个同等视觉权重的卡片。

### 7.6 文件列表 `SourceFileList`

新建任务、需求确认和生成进度复用同一文件行组件。固定列：

- 文件类型图标；
- 原始文件名；
- 文件大小；
- 当前状态；
- 进度或错误原因；
- 允许的操作。

状态文案固定为：`等待处理`、`解析中`、`切分中`、`向量化中`、`已就绪`、`处理失败`、`已移除`。

失败行必须显示具体原因和可执行操作，不能只显示红色图标。运行中使用进度条时必须同时显示状态文字。

### 7.7 模型状态 `ModelStatusCard`

固定展示字段：

- 模式：自动选择或手动选择；
- 首选模型；
- 实际模型；
- 是否降级；
- 降级原因；
- 查看调用记录入口。

未降级时不显示空的“降级原因”。发生降级时使用橙色非阻塞提示，不弹出错误对话框打断用户。

### 7.8 聊天助手 `ChatAssistantDrawer`

大纲编辑和文字结果共用同一个抽屉组件，不分别实现两套聊天 UI。

固定结构：

```text
标题 + 关闭按钮
当前对象 ContextChip
消息列表
澄清卡 / 影响确认卡 / 执行结果卡
输入框 + 发送按钮
```

固定规则：

- 桌面宽度 380px；小于 1280px 时以遮罩抽屉覆盖；
- 默认从右侧打开；
- 当前对象必须始终可见，例如 `当前对象：第四章` 或 `当前对象：第8页`；
- 未选择对象时显示 `当前对象：整份内容`，但发送后若范围不明确必须追问；
- 输入框固定在底部；
- 请求执行中禁用重复发送；
- 消息、确认卡和结果卡使用稳定 ID，刷新后可恢复；
- 高影响操作必须先显示影响范围和确认按钮；
- 成功后显示修改摘要、未影响范围、`撤销修改` 和 `再次修改`；
- 抽屉开关、宽度和结构在大纲页与结果页保持一致。

### 7.9 对话框 `AppConfirmDialog`

统一处理以下场景：

- 离开未保存页面；
- 删除上传文件；
- 取消正在运行的任务；
- 确认大范围重生成；
- 接受未达到评分阈值的当前结果。

按钮顺序固定为左侧取消、右侧确认。破坏性确认使用红色按钮，普通确认使用蓝色按钮。禁止使用浏览器原生 `confirm()`。

### 7.10 消息反馈

- 字段错误：紧邻字段显示；
- 页面级可恢复错误：内容区顶部 `Alert`；
- 操作成功：短暂 `Message`；
- 后台任务接受：提示“任务已开始”，随后进入进度页；
- 未知服务错误：显示 request ID 和重试建议，不显示堆栈；
- 版本冲突：显示统一对话框，说明内容已更新，并提供 `刷新页面`；
- 不能只用 Toast 承载需要用户处理的重要错误。

## 8. 页面详细设计

## 8.1 P01 任务中心

### 页面目标

让用户快速识别哪些任务正在运行、等待处理、已完成或可以重试，并进入正确页面继续操作。

### 页面结构

1. `AppHeader`；
2. `PageHeader`：标题、说明、`创建新任务`；
3. 状态摘要；
4. 搜索与筛选栏；
5. 任务表格；
6. 最近活动列表。

### 状态摘要

固定四项：`进行中`、`等待处理`、`已完成`、`失败可重试`。卡片可点击并更新表格筛选，但不是独立路由。

计数映射：

- 进行中：`FILES_PROCESSING`、`RUNNING`；
- 等待处理：`WAITING_REQUIREMENT_INPUT`、`WAITING_OUTLINE_CONFIRMATION`、`WAITING_USER_FEEDBACK`；
- 已完成：`COMPLETED`；
- 失败可重试：`FAILED_RETRYABLE`。

### 任务表格

固定列：任务名称、状态、当前阶段、目标页数、实际模型、更新时间、操作。

行主操作由 `resolveTaskAction(task)` 统一决定：

| 状态 | 操作文案 |
| --- | --- |
| 草稿 | 继续编辑 |
| 等待需求确认 | 确认需求 |
| 等待大纲确认 | 确认大纲 |
| 运行中 | 查看进度 |
| 等待用户处理 | 处理问题 |
| 已完成 | 查看结果 |
| 失败可重试 | 重试 |
| 已取消/最终失败 | 查看详情 |

更多菜单可包含重命名、取消或删除入口。首期若后端没有删除能力，不展示删除。

### 页面状态

- loading：摘要骨架 + 表格骨架；
- empty：说明尚无任务，并提供 `创建新任务`；
- filter empty：保留筛选条件，提示没有匹配结果；
- error：页面级错误和 `重新加载`；
- pagination：数据超过 20 条后分页，每页大小固定 20。

## 8.2 P02 新建/编辑任务

### 页面目标

收集原始需求、模型偏好和参考资料，保存草稿并启动需求解析。

### 页面结构

1. `AppHeader`；
2. `PageHeader`；
3. 左侧 `RequirementForm`；
4. 右侧 `SourceFileUploader` 与 `SourceFileList`；
5. `FlowActionBar`。

桌面使用 56% / 44% 两列布局。两列顶部对齐，右侧文件列表内容过长时在页面内自然增长，不设置过矮的内部滚动区。

### 需求表单

字段顺序固定：

1. 主题；
2. 目标页数；
3. 使用场景；
4. 目标受众；
5. 内容风格；
6. 特殊限制；
7. 模型选择。

主题、目标页数、使用场景、目标受众和内容风格为首期表单必填。特殊限制选填。

校验规则：

- 主题 1..200 字；
- 目标页数使用数字输入，默认限制 3..50；
- 特殊限制最多 500 字；
- 失焦后显示字段错误，提交时聚焦第一个错误；
- 服务端错误映射回对应字段；无法映射的显示在表单顶部。

### 模型选择

使用单选卡片：`自动选择` 加后端返回的可用模型。实际模型列表来自 `GET /models`，不得硬编码只有三项。

- 默认选择自动模式；
- 自动模式显示简短说明；
- 模型不可用时 disabled，并显示不可用原因；
- 不向用户展示模型 ID、API 地址或密钥信息。

### 文件上传

- 支持拖拽和点击；
- 支持 PDF、Markdown、TXT、DOCX；
- 文案不得笼统写 Word 而接收旧 `.doc`；
- 上传前显示大小和数量限制；
- 文件逐个上传和逐个展示状态；
- 失败文件不阻塞编辑表单，但解析需求前必须移除、重传或明确忽略；
- 文件列表禁止提供“清空全部”而不确认。

### 页面操作

- 次操作：`保存草稿`；
- 主操作：`解析需求`；
- 没有 `上一步`；
- 主操作发起前先保存当前草稿；
- 重复点击由按钮 loading 和幂等键共同防止；
- 接口返回 `202` 后进入结构化需求确认页或等待解析状态。

效果图中的 `开始生成` 统一改为 `解析需求`，因为此时还没有经过结构化需求和大纲确认。

## 8.3 P03 结构化需求确认

### 页面目标

让用户检查系统解析结果，明确处理缺失、冲突和无法理解的条件，禁止系统悄悄猜测。

### 页面结构

1. `AppHeader`；
2. `TaskContextHeader`；
3. `WorkflowStepper`，当前阶段为 `需求解析`；
4. 左侧结构化需求表单；
5. 右侧待确认项、文件状态和模型估计；
6. `FlowActionBar`。

### 结构化需求表单

至少展示：主题、目标页数、场景、受众、风格、语言、资料使用偏好、特殊限制和用户原始描述。

- 普通字段可以编辑；
- 用户原始描述默认折叠且只读；
- 冲突字段使用橙色边框、冲突说明和明确选项；
- 缺失字段不能用模型推测值伪装为用户输入；
- 所有待确认项解决前主操作保持 disabled；
- 用户修改后立即执行客户端一致性校验。

### 右侧信息

- `需要您确认 N 项`：只列当前阻塞问题；
- `资料状态`：复用 `SourceFileList`；
- `模型选择`：显示当前偏好和复杂度初估，可返回编辑页更改。

### 页面操作

- 上一步：固定 `上一步`；
- 主操作：`确认需求并生成大纲`；
- 提交成功后进入大纲编辑页；
- 生成大纲期间可先进入进度页，再由任务状态跳转到大纲页；具体采用哪种过渡方式由接口响应决定，但不能在按钮上长时间等待。

## 8.4 P04 大纲编辑

### 页面目标

让用户检查章节、条目和页数分配，并通过直接编辑或大纲助手完成修改。

### 页面结构

1. `AppHeader`；
2. `TaskContextHeader`；
3. `WorkflowStepper`，需求解析为 completed，大纲规划为 active；
4. 左侧任务概览、资料状态和模型状态；
5. 中间 `OutlineEditor`；
6. 右侧 `ChatAssistantDrawer`；
7. `FlowActionBar`。

抽屉关闭时，中间区域扩展使用空出的宽度；抽屉打开时不能压缩中间编辑区到不可用宽度。

### 大纲编辑器

每个章节行包含：

- 拖拽手柄；
- 展开/收起；
- 章节标题；
- 章节目标；
- 页数步进器；
- 编辑操作；
- 更多菜单。

展开后显示子条目和各自页数。页数规则：

- 顶部始终显示 `已分配 X / Y 页`；
- X 等于 Y 时使用蓝色或绿色正常状态；
- X 不等于 Y 时使用橙色，并禁用主操作；
- 页数不得小于章节内条目数量；
- 调整章节页数后应按明确规则重新分配子条目，不得静默丢失条目；
- 拖拽后立即更新顺序但标记为未保存。

### 大纲助手

- 用户选中章节或条目时更新当前对象；
- 修改目标明确且影响小，可以直接应用；
- 影响已生成内容时显示影响确认卡；
- 影响卡必须列出页面范围；
- 用户只可选择 `暂不生成` 或 `重新生成相关页面`，不得默认重生成整份；
- 成功修改后中间大纲立即同步，不允许聊天结果和大纲显示不同内容。

### 页面操作

- 上一步：固定 `上一步`；
- 主操作：`确认大纲并开始生成`；
- 保存状态显示 `未保存`、`保存中`、`已保存` 或 `保存失败`；
- 确认后进入生成进度页；
- 已经存在正文时改变大纲，需要先显示影响范围确认。

## 8.5 P05 生成进度

### 页面目标

展示长任务的当前阶段、已经完成的结果、失败原因、模型降级和需要用户处理的动作。

### 页面结构

1. `AppHeader`；
2. `TaskContextHeader`；
3. `WorkflowStepper`；
4. 左侧运行记录；
5. 左下资料处理状态；
6. 右侧当前状态或人工处理区；
7. 右下模型状态。

本页不使用 `FlowActionBar`，也不显示 `上一步`。用户不能通过返回按钮让运行中的工作流回到已完成节点。

### 运行记录

固定节点：需求解析、大纲规划、资料检索、内容生成、质量评估、自动修订。

每行展示：步骤、状态、执行结果、实际模型、完成时间、查看详情。

- 节点状态来自服务端；
- 未开始节点显示 `等待中`；
- 当前节点显示 `执行中` 和阶段内进度；
- 页内容生成可显示 `已完成 7 / 15 页文字内容`；
- 不显示虚假的总体百分比；
- 刷新页面后从服务端恢复，不重新从 0 播放进度。

### 轮询规则

- 页面可见且任务运行中：每 2 秒；
- 页面不可见：每 10 秒；
- 等待用户、完成、失败或取消：停止轮询；
- 轮询失败采用退避，不用连续弹 Toast；
- 状态变为 `WAITING_OUTLINE_CONFIRMATION` 时进入大纲页；
- 状态变为 `COMPLETED` 时进入结果页，或给用户明确的 `查看结果` 操作；
- 不因一次网络失败把任务标成失败。

### 运行中状态

右侧显示当前节点、阶段内进度、简短说明和取消任务入口。取消任务必须二次确认。

### 自动修订达到上限

右侧改为人工处理面板，包含：

- 当前评分；
- 尚未解决的问题；
- 补充修改意见；
- 修改范围；
- `提交意见并继续`；
- `指定范围重新生成`；
- `接受当前结果`。

这三个操作必须使用清晰不同的语义，不得把“接受当前结果”做成默认主操作。

### 可恢复失败

显示：失败节点、错误类型、用户可读原因、已经完成的节点、首选/实际/备用模型记录，以及允许操作：

- `重试失败节点`；
- `调整模型并重试`；
- `返回任务中心`。

不得显示“重新开始全部任务”，除非用户明确选择新建任务。

## 8.6 P06 文字结果

### 页面目标

以纯文字方式查看、修改、评估和导出演示文稿文案。

### 页面结构

1. `AppHeader`；
2. `TaskContextHeader`；
3. `WorkflowStepper`，全部 completed；
4. 结果标签页；
5. 左侧文字目录；
6. 中间纯文字正文；
7. 右侧 `ChatAssistantDrawer`；
8. 页面级复制和下载操作。

### 结果标签页

固定顺序：

1. `正文内容`；
2. `质量评估`；
3. `Markdown 源码`；
4. `修改历史`。

标签顺序和文案不得在页面间变化。切换标签不改变路由顶级页面，可用 query 参数 `?tab=content|evaluation|markdown|history` 支持刷新恢复。

### 正文内容

使用三栏布局：

- 左侧 `ContentOutlineTree`：章节和逻辑页文字目录；
- 中间 `PageTextSection`：标题、要点、演讲备注、资料依据和待核实项；
- 右侧聊天助手。

禁止使用 `SlideCard` 作为视觉画布。开发指导中的 `SlideList / SlideCard` 在前端实现中统一替换为：

- `ContentOutlineTree`；
- `PageTextSection`；
- `CitationList`；
- `VerificationNoteList`。

`PageTextSection` 是普通文档流容器：

- 宽度随中间栏变化；
- 不固定 16:9；
- 不绘制幻灯片边框；
- 不使用背景图、图形或布局模板；
- 标题和要点都是可复制文本；
- 页面之间通过分隔线和页码标题区分。

### 质量评估

展示：

- 总分与通过状态；
- 完整性、逻辑性、内容质量、需求符合度；
- 硬性检查；
- 问题列表；
- 修改建议；
- 触发过的修订记录。

分数条只是数值可视化，不得使用雷达图、仪表盘等过度视觉化图表。问题可以点击并定位对应逻辑页。

### Markdown 源码

- 只读代码编辑器或等价文本区域；
- 保留原始 Markdown；
- 支持复制；
- 支持 `.md` 下载；
- 默认禁用原始 HTML；
- 预览区和源码区明确区分；
- 不把渲染后的 Markdown 包装成幻灯片。

### 修改历史

按时间倒序展示：版本、修改类型、范围、来源、摘要、评分变化和操作者。

允许撤销时显示 `撤销到此版本` 或 `撤销修改`。是否允许由后端返回，前端不能只根据序号判断。

### 内容助手

- 当前对象为用户选中的逻辑页或章节；
- 明确的局部修改可以执行；
- 修改后重新评估；
- 成功后展示 `修改 N 处 · 未影响 M 页`；
- 提供撤销和再次修改；
- 影响页数、全局结构或超过 30% 内容时先确认；
- 中间正文必须在操作完成后重新获取，禁止只更新聊天消息。

### 页面操作

- `复制 Markdown`：复制原始 Markdown，不复制 HTML；
- `下载 .md`：下载 UTF-8 Markdown；
- `重新生成本页文字`：只作用于当前逻辑页；
- 不显示 `上一步`；
- 不允许返回流程中间节点后直接覆盖已完成内容；需要修改时通过页面内编辑或聊天工作流执行。

## 9. 通用交互状态

### 9.1 Loading

- 首次页面加载使用与实际布局相似的骨架；
- 按钮提交使用按钮内部 loading；
- 表格和目录局部刷新不清空整个页面；
- 聊天执行时在消息区显示进行状态；
- loading 超过 10 秒显示当前操作说明，但不展示不可信 ETA。

### 9.2 Empty

每个 Empty 必须说明：当前为什么为空、用户可以做什么。禁止只显示空白插画。

示例：

- 无任务：`还没有生成任务` + `创建新任务`；
- 无上传资料：`未上传参考资料，仍可不使用资料继续`；
- 无引用：`当前页面没有使用上传资料`；
- 无聊天记录：`可以询问或修改当前内容`；
- 无修改历史：`当前内容尚未产生修订记录`。

### 9.3 Error

错误信息结构固定：

```text
发生了什么
影响了哪一步
用户可以做什么
request_id（仅服务错误）
```

不得把模型供应商的原始异常或堆栈直接显示给用户。

### 9.4 Unsaved

可编辑页面统一使用：`未保存`、`保存中`、`已保存`、`保存失败`。离开有未保存数据的页面时统一拦截。

### 9.5 Version conflict

HTTP 409 且错误码为 `VERSION_CONFLICT` 时：

1. 停止当前提交；
2. 显示内容已被更新；
3. 提供 `刷新页面`；
4. 不自动覆盖服务端版本；
5. 用户未提交的长文本应暂存在前端，刷新后允许复制恢复。

## 10. 路由离开和返回规则

### 10.1 通用上一步

只有结构化需求确认和大纲编辑需要显示 `上一步`。新建任务没有上一步；进度和结果不是可逆表单步骤，不显示上一步。

### 10.2 浏览器返回

- 浏览器返回不能绕过未保存确认；
- 从进度页返回任务中心不取消任务；
- 从结果页返回任务中心不改变任务状态；
- URL 直接打开受限页面时先读取任务状态，再重定向到正确页面；
- 不依赖内存中的上一页信息决定关键跳转。

### 10.3 页面刷新

刷新后必须仅凭 `taskId` 和 query 参数恢复：

- 当前任务；
- 当前标签页；
- 当前选中的章节或逻辑页；
- 聊天历史；
- 等待确认的变更请求；
- 服务端任务状态。

聊天抽屉是否展开、目录折叠状态等纯 UI 偏好可以存 Pinia 或 session storage。

## 11. 前端状态与数据管理

### 11.1 服务端状态

TanStack Vue Query 管理：

- 任务列表和任务详情；
- 模型目录；
- 文件列表；
- 结构化需求；
- 大纲；
- 页面文字内容；
- 评估结果；
- 模型调用记录；
- 对话消息；
- 修改历史；
- Markdown。

Query key 集中定义，例如：

```ts
taskKeys.detail(taskId)
taskKeys.files(taskId)
taskKeys.outline(taskId)
taskKeys.content(taskId)
taskKeys.evaluation(taskId)
taskKeys.chat(taskId)
taskKeys.revisions(taskId)
```

Mutation 成功后使相关 Query 失效并重新获取，禁止同时手工修改多份服务器缓存。

### 11.2 本地 UI 状态

Pinia 只保存：

- 当前选中章节/逻辑页；
- 聊天抽屉开关；
- 目录折叠状态；
- 未提交表单草稿；
- 页面筛选和排序；
- 用户界面偏好。

任务状态、文件状态、模型状态和内容版本不得只存在 Pinia。

### 11.3 表单状态

表单字段值和字段错误由表单层管理。保存草稿成功后更新基线；只有字段值偏离基线才显示未保存。

## 12. API 交互映射

| 页面/组件 | 主要接口 |

| 启动解析 | `POST /tasks/{id}/start` |
| 任务状态 | `GET /tasks/{id}` |
| 大纲 | `GET /tasks/{id}/outline`、`PUT /tasks/{id}/outline`、`POST /tasks/{id}/outline/confirm` |

## 13. 响应式设计

### 13.1 桌面优先

首期主要面向桌面浏览器：

- `>= 1440px`：完整三栏；
- `1280..1439px`：缩小侧栏，保持主要内容可读；
- `1024..1279px`：聊天改为覆盖式抽屉，左侧目录可折叠；
- `< 1024px`：保证基本查看和必要操作，但不作为首期精细优化目标。

### 13.2 多栏收缩顺序

优先保持中间主内容宽度：

1. 减少左右栏宽度；
2. 将聊天助手改为覆盖抽屉；
3. 将左侧概览或目录改为可折叠侧栏；
4. 最后才允许主要表格横向滚动。

不得通过缩小正文字号解决空间不足。

### 13.3 小屏底部操作栏

FlowActionBar 在小屏改为两行时，`上一步`仍位于左侧，主操作仍位于右侧或下一行右侧。文案、样式和操作顺序不得改变。

## 14. 可访问性

- 所有表单字段有可见 label；
- 必填状态不能只用红色星号，错误文本要说明；
- 键盘可以完成上传、表单、标签页、目录、对话框和聊天发送；
- focus ring 使用 `--color-focus`，不得移除；
- 图标按钮提供 `aria-label`；
- 状态变化通过文字和适当的 live region 通知；
- 对话框打开后锁定焦点，关闭后返回触发元素；
- 抽屉关闭后焦点返回聊天入口；
- 颜色对比满足 WCAG AA；
- 动画尊重 `prefers-reduced-motion`；
- 表格在屏幕阅读器中保留表头关系；
- Markdown 链接使用安全的新窗口提示。

## 17. 测试与验收

### 17.1 通用组件一致性

必须通过以下检查：

- 所有业务页面的 AppHeader 高度、导航文案和激活样式一致；
- 所有出现的 WorkflowStepper 阶段、顺序、高度、颜色和状态规则一致；
- 所有 `上一步` 按钮文案、图标、位置、尺寸和 variant 一致；
- 大纲页和结果页使用同一个 ChatAssistantDrawer；
- 相同任务状态在任务中心、任务头和进度页颜色一致；
- 相同文件状态在三个页面的文案和颜色一致；
- loading、disabled、error 和 focus 状态不是页面自定义版本。

### 17.2 页面验收

#### 任务中心

- 状态卡筛选有效；
- 行操作根据任务状态进入正确页面；
- 空、错、加载和分页状态完整。

#### 新建/编辑任务

- 表单校验完整；
- 模型列表来自接口；
- 文件逐项显示状态；
- 主按钮文案为 `解析需求`；
- 重复点击不创建重复任务。

#### 结构化需求确认

- 冲突项未解决时不能继续；
- 用户原始描述可查看但不可被覆盖；
- `上一步` 和主操作符合统一规范。

#### 大纲编辑

- 页数合计实时更新；
- 页数不一致时不能确认；
- 聊天修改会同步更新中间大纲；
- 高影响修改先确认；
- `上一步` 不发生样式和文案变化。

#### 生成进度

- 轮询频率正确；
- 不显示虚假总百分比；
- 模型降级可见；
- 失败节点和恢复操作明确；
- 自动修订上限后可以反馈、局部重生成或接受结果。

#### 文字结果

- 全部内容以纯文字呈现；
- 不存在 PPT 缩略图、画布或模板；
- 目录可以定位逻辑页；
- 评估问题可以定位内容；
- 聊天修改保留未涉及页面；
- Markdown 可以复制和下载；
- 修改历史和撤销入口依据服务端能力显示。

### 17.3 响应式验收

至少检查 1600、1440、1280、1024 和 768 宽度：

- 主内容不被裁切；
- 表格列有合理优先级；
- 聊天抽屉不会把正文压到不可读；
- 长标题和文件名正确省略；
- 操作栏不会遮挡内容；
- 不通过缩小字体解决布局问题。

### 17.4 视觉对照

实现后分别与 6 张效果图对照以下项目：

1. 浅天蓝/白色的整体色温；
2. 顶部导航和页面头层级；
3. 主面板的边框、圆角和留白；
4. 表格和列表密度；
5. 主次按钮权重；
6. 聊天抽屉结构；
7. 长文本阅读体验；
8. 状态颜色和图标。

对照目标是保持设计语言，不是复制效果图中的错误或示例数据。

## 18. 低级模型实现约束

低级模型实现前端时必须遵守：

1. 先实现 tokens 和不可变通用组件，再实现页面；
2. 不允许在页面文件中复制 WorkflowStepper、FlowActionBar 或 ChatAssistantDrawer；
3. 不允许改变固定阶段、固定文案和状态映射；
4. 每完成一个页面，至少补充该页面的组件测试和关键交互测试；
5. 不允许用静态效果图代替真实 HTML、表单和交互组件；
6. 不允许写死任务、文件、模型、评分或聊天数据作为正式逻辑；
7. 不允许加入 PPT 视觉预览或模板功能；
8. 不允许仅为了贴近截图而违反任务状态和接口语义；
9. 出现效果图与本文差异时使用第 16 节的实际实现要求；
10. 完成前检查第 17 节全部验收项，不得只验证构建成功。

推荐实现顺序：

```text
设计令牌
-> AppShell / AppHeader
-> WorkflowStepper / FlowActionBar / 状态组件
-> TaskCenterView
-> TaskEditView
-> RequirementReviewView
-> OutlineEditorView + ChatAssistantDrawer
-> GenerationProgressView
-> TextResultView
-> 响应式与可访问性
-> 全流程端到端测试
```

## 19. 最终一致性定义

前端只有同时满足以下条件，才能认为设计实现一致：

- 页面数量保持为 6 个核心页面；
- 工作流阶段和页面数量不再混淆；
- 顶部导航、流程条、上一步、操作栏、状态标签和聊天抽屉均由共享组件提供；
- 同一组件在不同页面没有未声明的视觉变体；
- 页面跳转由任务状态决定，刷新后可以恢复；
- 所有结果内容保持纯文字和 Markdown 形态；
- 错误、模型降级、人工反馈和局部修改都有可执行操作；
- 效果图只提供风格和布局参考，实际交互符合需求和后端契约；
- 6 个页面、通用状态和响应式布局均通过验收测试。
